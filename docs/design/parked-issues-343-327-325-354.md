# Design notes for the parked issues

Working notes for #343, #327, #325 and #354, written so someone can pick them up later. This is a
design record, not a commitment to build, and no code changes with it. Where a claim is a guess it
says so.

## #343: class-specific oracles

Today `decideOutcome` in `lib/reproduction/decide.ts` has one signal: a canary seeded by a trusted
fixture and found again in a response. That fits injection and SSRF with a callback. It has nothing
for an access-control bug, where no canary is echoed.

Approach: keep the canary model. `decideOutcome` only compares the fixture, control and exploit legs,
and the check itself is a per-recipe `oracleCheck`, so an access-control bug fits it: the exploit reads
another principal's resource and the canary shows up, while the control reads the caller's own resource
and must stay clean. What a recipe lacks is per-run state, so a recipe can carry `setup` steps whose
responses are captured and substituted into later requests (`feat/class-oracles-343`). `createReproducer`
and `runLeg` in `lib/sandbox/reproduce.ts` stay the driver.

What is built, against the pinned Juice Shop target:

- IDOR and broken access control: `juice-shop-idor-basket` seeds two principals through the
  trusted registration path. A reading B's basket is `REPRODUCED`; the primary control is A reading
  A's own basket. The third-principal guard is built: `additionalNegativeControls`
  (`lib/reproduction/types.ts`, `lib/targets/recipes.ts`) runs a principal-free request after the
  primary control stays clean, folding its result into the same control leg. An endpoint open to
  everyone shows the canary to that principal-free request too, so the run is `ANALYSIS_ONLY`
  rather than being scored as a cross-principal IDOR.
- Broken access control, write path: `juice-shop-product-tampering-unauth` is an unauthenticated
  write (`PUT /api/Products/:id`) with an authenticated write as the negative control, and a
  follow-up read as the oracle, since the write's own echo proves nothing about persistence.
- Path traversal: `juice-shop-ftp-poison-null-byte` reads back a backup file a poison null byte
  smuggles past the extension allowlist, against a public file as the control. This is the one
  shipped traversal oracle; it is specific to this target's filter, not a generic sentinel-file
  check.
- SSRF: `juice-shop-ssrf-profile-image` is built. The orchestrator boots an isolated,
  internet-blocked listener sandbox joined to the target and exposes its address as `{{oobUrl}}`.
  No listener hit means `NOT_REPRODUCED`, not a guess from the exploit's own response.
- Setup and capture: a recipe can carry `setup` steps whose responses are captured and substituted
  into later requests (login tokens, basket ids, the listener's callback URL). `createReproducer`
  and `runLeg` in `lib/sandbox/reproduce.ts` stay the one driver for every class above.

What remains: a live proof run of these recipes against the pinned Juice Shop snapshot, beyond the
mocked end-to-end tests. A generic sentinel-file traversal oracle that does not depend on one
target's filter, and class oracles for targets other than Juice Shop, are out of scope here.

Invariants that do not change: no bound target means `ANALYSIS_ONLY`; the agent's own claim never
sets the outcome; a negative control that finds the signal means neither leg can be trusted, so the
result is `ANALYSIS_ONLY`, not a guess.

## #327: pentest workbench

`docs/pentest-workbench.md` already holds the design and its phases. Build Phase 0 only: a slim image
with nuclei, httpx and newman, joined to the target's linked-sandbox group under `networkBlockAll`,
driven by exec, with its output handed to the agent as evidence. The oracle is untouched. Stop there
unless verdict quality measurably improves.

The scope manifest in Phase 1 is the security-sensitive part. It lands with adversarial tests before
any heavier tool (ZAP, sqlmap) is added. A scan hit stays a lead; it only becomes a verdict through
an oracle run from #343.

## #325: black-box and live-target reproduction

The issue is a placeholder, so this needs a design before any code. The full design is in
[`325-live-target-reproduction.md`](325-live-target-reproduction.md).

- Binding: Q33 in `docs/decisions.md` already says a live host counts as authorised only with a
  current, re-verified ownership proof. Start with a DNS TXT record or a `.well-known` file, checked
  before every run and expiring.
- What runs: only the #343 oracles. There is no throwaway sandbox here, so requests are rate limited
  and anything that writes needs an explicit reviewer opt-in.
- Open for the owner: legal exposure of sending traffic to a host BountyDesk does not control, abuse
  handling, and how a proof is revoked.

## #354: per-tenant registry

`RegistryHandoff` in `lib/build-onboarding/registry.ts` already owns push, digest read and delete.
The work is an implementation per tenant whose namespace and credential come from a tenant secret
store, not global `REGISTRY_*` env. `docs/research/354-per-tenant-registry.md` compares GHCR, ECR,
Artifact Registry and ACR; ACR scoped tokens map most directly to one token per tenant namespace.
Add a test that tenant A's credential cannot pull or delete tenant B's image.

Possible blocker: #326 is closed as completed, but `lib/db/schema.ts` has no tenant or secret-store
tables. The issue says not to build before tenancy exists, so confirm what #326 delivered first.

## How this could differ from other products

These are hypotheses to check, not findings. The market claims below come from vendor-authored
comparison articles, and Konvu's capabilities are unverified beyond the gap list in
`docs/site/competitor-audit.html`.

- Verdicts that carry their deciding evidence and a clean negative control, with `ANALYSIS_ONLY` as the
  answer when the control is dirty, instead of an exploit claim taken from an agent transcript.
- A workbench with no egress path to filter, rather than a DNS blocklist, with the human-approved
  `publish_verdict` gate unchanged.
- Live-target runs that re-verify ownership every time.
- A per-class false-positive rate from the benchmark in #346, so accuracy is measured.
