Accessibility

What the shipped web product does today, read from its components and app/globals.css, then what the proposed mobile app does in its prototype screens. Gaps are marked as gaps. Nothing here comes from an assistive technology test run: no screen reader pass, keyboard audit or automated checker has been recorded in the repo.

Web product, today

Color is never the only signal

Every phase dot is aria-hidden and sits beside a label that says the same thing in words (components/phase-dot.tsx). PhaseBadge carries the state name and is not hidden. Report ids and handles get a sr-only span where the visible text is an icon or abbreviation (the home page and the case file header).

Labels and roles

About 30 aria-label attributes on search boxes, icon buttons and groups ("Search the review queue", "Message to Agent Bounty", "Remove {email}", "Digit 3" on the one-time code input). Errors use role="alert"; progress text uses role="status". The repository filter in the reports table is a combobox with a listbox of options.

Live regions

Three aria-live="polite" regions: the route loading state, the approval dialog, and the reviewer chat. The agent chat names its busy state ("Agent Bounty is thinking").

Focus styles

The shared button has a focus-visible border and ring, and the destructive variant its own tinted ring (components/ui/button.tsx). The prompt bar uses focus-within on its pill. The button is built on the Base UI primitive; dialog focus handling was not checked.

Touch targets

The default button is 44 pixels high (h-11), large is 48, and the icon button is 44 square. Some sizes fall under 44: sm at 40, icon-sm at 40 (size-10), and the xs and icon-xs sizes at 28 pixels. Where those are used was not audited.

Keyboard

Navigation is real links and buttons, so tab order follows the document. The reports filter combobox has combobox, listbox and option roles. Two shortcuts exist: Cmd or Ctrl+B toggles the sidebar (components/ui/sidebar.tsx) and "/" focuses search in the integrations list (integration-list.tsx). A full keyboard path test has not been done.

Reduced motion, per keyframe

app/globals.css defines seven animations. Each one is paired with a motion-reduce rule or a useReducedMotion check where it is used. Nothing in the stylesheet itself uses @media (prefers-reduced-motion); the answer lives at the call site, so a new use of one of these classes has to remember it.

Proposed mobile app Proposed, not built

The 28 prototype screens in screens/ (Variant C) are HTML, not React Native. What they do is a design intent; none of it has been tested with VoiceOver or TalkBack. The CSS is one kit, screens/c.css, with behavior in c.js. The app is iOS and Android only. On the web, phones use the responsive desktop app: its landing, sign-in and submit pages were checked at 390 px with no horizontal scroll, and the reviewer pages behind sign-in were not checked.

How the Expo app would meet these (proposed)

None of this is built or tested. It is the plan for turning the prototype's intent into React Native behavior, in the order the open items are listed below.

VoiceOver and TalkBack

  • Every aria-label in the screens becomes an accessibilityLabel; aria-current, aria-expanded and aria-checked become accessibilityState.
  • Review next keeps its count in the label, not in the badge: "Review next verdict, 3 waiting". The bell keeps "Inbox, 2 unread".
  • Rows that push a screen get the button role and a hint ("Opens the timeline"). Static rows are read as one element: title, value, subtitle.
  • The phase pill label is the phase name, so it reads the same as it looks. Decorative icons and mascots are hidden.
  • The six code boxes are grouped and announced as "Digit 1 of 6". The sandbox and onboarding diagrams get one label that states the result, with the steps as a list.
  • A toast should be announced without taking focus. A sheet (deny, target material) should move focus into itself and return it on close; its X and check buttons need labels.
  • @expo/ui renders real SwiftUI and Compose controls, which bring their own reader semantics. The parts drawn with StyleSheet need the props set by hand.

Dynamic Type and font scale

  • Text follows the system font size by default in React Native. The plan keeps that on and sets a maximum multiplier on dense pieces (tab labels, pills, meta) so the floating bar does not break.
  • Row, button and sheet heights are minimums, not fixed values, so a larger font grows the row. Fixed card widths (286 and 112) become flex or minimum widths. The 390 by 844 frame does not constrain the app.
  • Long titles wrap to two lines (the report row already clamps at two) rather than truncate at large sizes.
  • Check with the system font at its largest setting and display zoom on, on both platforms, before calling it done.

Reduced motion with Reanimated

  • Reanimated 4 can read the system reduced-motion setting, so each animation gets a reduced variant in code.
  • Screen pushes become a short crossfade. The sheet and toast fade with no travel. The long press lift becomes an opacity change.
  • Haptics from expo-haptics stay available as extra feedback and never carry the only signal.

Touch targets

  • Minimums are 44 pt on iOS and 48 dp on Android. The Android rules in c.css already raise chips, segmented items and the section more button to 48.
  • The switch stays its native size and the row is the target. A switch placed outside a row needs hitSlop.
  • The long press menu is exposed as custom accessibility actions for screen reader and switch users.
M4 Home, the Needs you carousel and Review next M6 Reports, search and filter chips with a no-results state M18 OTP verify, six boxes with digit labels

Before building: run VoiceOver and TalkBack over the real app, set the fonts to scale with a cap, give a bare switch a larger hit area, expose the long press menu as custom actions, and decide the Closed phase ink. Those are the open items, in that order of effort.
