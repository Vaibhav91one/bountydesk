Onboarding follow-ups

The four items docs/onboarding-follow-ups.md lists as still open. Each now has an issue above.

ItemWhere it standsIssue
Tarball without a DockerfileThe upload build plan always uses a Dockerfile at the archive root. The onboarding agent that writes one for GitHub repos is not wired to uploads.#351
Non-GitHub git URLThe git source kind accepts any clone URL, but no intake or onboarding path produces one.#352
Mesh image reclaim, non-GHCR deleteSingle-image builds reclaim after the snapshot is active (needs REGISTRY_DELETE_TOKEN). The mesh path pushes one image per service and does not.#353
Private registry at multi-tenant scaleZot (a single binary) or Harbor (per-project RBAC) are the options named. It belongs to the multi-tenancy work.#354

A limit rather than a gap: Alpine-based targets fail to build on a restricted Daytona tier because the org egress policy does not reach the apk mirror. That is a billing-tier choice, and a Debian base builds fine.
